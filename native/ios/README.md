# Fictional iPhone and Apple Watch companion

`../PDBridgeNative.xcodeproj` is a generated two-target SwiftUI project. The iPhone target has a one-time first-launch welcome followed by Home, History and Appointment screens modeled on PD Bridge's calm, large-control interface. The welcome uses the existing app mark and directs new installs to Home without login; a prior local diary or saved preference bypasses it. The Home Help action is labeled “Call a caregiver” and remains a manual, temporary, user-confirmed Phone handoff, not emergency response. The watch target has one **Send Fictional Test Event** action and a retry control. It never detects a fall. The browser app and Friends Preview are untouched.

The watch sends only a fixed fictional fall-test kind, a UUID and a timestamp through WatchConnectivity `transferUserInfo`. It keeps the ID in a versioned, atomic file-backed fictional outbox until the phone sends an application-level receipt **after** a successful vault write. The phone can first send a non-final “received, not saved” state; storage failure returns a retry state without clearing the Watch queue; a pre-deletion event receives a terminal rejection; only a durable save or already-stored duplicate receives the final stored response. The Watch persists its last stored/rejected result so that status survives relaunch. The queue is capped, excluded from backups, and protected after first unlock; it contains no note text. The phone validates the exact payload, encrypts a pending observation in `ProtectedObservationVault`, and retains an opaque processed-ID ledger even if the observation is deleted. History shows the source and event ID. A person must confirm the event and select it for an Appointment report. Duplicate delivery cannot create a second entry. Editing preserves original wording and prior wording.

The iPhone vault uses AES-GCM with a device-only Keychain key available only when unlocked, complete file protection, and backup exclusion. A storage error leaves the in-memory record unchanged and never triggers the watch receipt. iOS protected-data notifications clear the service's decrypted record cache and block writes while the device is locked; after unlock, the archive is reloaded before the UI is repopulated. A failed Watch write is not acknowledged; the watch retains its original ID, resends when the paired session becomes reachable, and also offers a Retry control. This lock/retry behavior is contract-tested with simulated protected-data notifications and `errSecInteractionNotAllowed`, but has not been exercised on an iPhone.

Future Samsung/Wear OS support is not implemented. Keep platform adapters at the edge and normalize any later event into a versioned, source-attributed envelope with a durable event ID, occurrence time, phone receipt time, pending confirmation, and idempotent storage acknowledgment. The existing `FictionalWatchEvent` is an Apple-specific fixed test protocol, not a cross-platform schema. Samsung documents fall-event delivery through Health Services passive monitoring on Galaxy Watches; the capability and permissions must be checked on the exact model/OS before development. For an offline-tolerant paired-device queue, Android's persistent `DataClient`/`DataItem` is a better fit than ephemeral `MessageClient`, which has no persistence or retry. The Wear OS Data Layer works between a watch and an Android phone, not an iPhone, so a Samsung wearable would require a separate Android phone companion before any future bridge. No Wear OS module, fall permission, or real event listener is present.

Settings offers passphrase-encrypted backup export/import, non-destructive merge, and confirmed deletion of the local key and observation file. Importing an older backup can restore entries deleted locally after that backup was created; the import confirmation discloses this. Delete-all first clears app-owned record, undo, editor, search and backup-passphrase state, then persists a deletion intent in two independent stores. The vault proceeds if either intent is durable, blocks writes/imports/Watch delivery, independently attempts to remove the key and ciphertext even if one store fails, writes a small device-only completion timestamp only after both operations succeed, and only then removes pending markers. The retained timestamp prevents older queued Watch events from restoring deleted entries; a new local entry or explicit backup import is required before new Watch events can create a vault again. If deletion fails, the UI shows an incomplete/error state and offers retry; launch resumes a durable pending deletion. This does not physically overwrite flash storage, and encrypted backup files saved elsewhere are outside local deletion. A user-managed encrypted backup can be moved to another device, but PD Bridge does not sync it or recover a lost passphrase. The native backup crypto and Keychain/file vault have been tested on this Mac; iPhone-specific file protection, lock/restart notifications and deletion behavior remain unverified on hardware. This project is **fictional-only**, not approved for patient information.

The earlier proposal to use a nonpersistent WKWebView and a message bridge was not implemented. A small native SwiftUI interface avoids putting observation text in WebKit storage and can call the vault directly. The native app has Home with grouped one-tap shortcuts, searchable/filterable History that finds original and earlier wording, visible edit state, Appointment count tiles and source references, print, Comfort Mode, and English plus draft Gujarati/Hindi/Urdu labels with Urdu right-to-left layout. Appointment now distinguishes an empty diary from saved entries set aside for this report, and confirmed entries can be included or set aside directly from the Appointment screen while remaining in History. Manual-note timestamps are labeled as the time recorded in PD Bridge; they are not presented as verified event times because the manual editor has no separate occurrence-time field. External records can preserve a source occurrence time and a later PD Bridge receipt time. Storage notices distinguish success, information and failure and offer a local-storage retry; backup export/import now require explicit confirmation. Draft translations are not fluent-reviewed; privacy and fictional-data warnings remain in English. An optional English Talk demonstration uses only fixed fictional choices in a local scripted conversation, includes a review-before-save screen, and never requests the microphone or calls speech/AI services. The separate voice-note action can record up to two minutes, tag the spoken language as Gujarati, Hindi, Kutchi, or another listed option, then replay and explicitly save the original audio without a transcript. Microphone permission is requested only after the person taps Start. The protected temporary file is deleted after review; saved audio is embedded in the encrypted vault and encrypted user-exported backups. Each voice attachment is limited to 512 KiB. Optional medication reminders are scheduled by iOS locally, use no medication names or dose, and may be delayed or missed; permission is requested only when enabling the reminder. V1 Help uses manual, temporary name-and-number entry followed by an in-app review. The user must then explicitly tap Open Phone; Phone may require another confirmation. PD Bridge does not save the details, share location, call automatically, or monitor emergencies. Larger text wraps, Note Editor scrolls, and grouped Home/Appointment layouts become single-column in Comfort Mode or accessibility Dynamic Type.

On 2026-11-04/05, the iPhone 14 simulator build was installed and launched and the fictional capture, History correction/search, Appointment inclusion/exclusion/report preview, backup merge, deletion/Undo, Comfort Mode, larger text, Talk demo, English/Urdu RTL and persistence flows were visually exercised. The Watch companion launched on a paired Apple Watch Series 11 simulator. Its fictional event stayed queued; no Watch-origin event was saved/acknowledged on the iPhone. The project notes that Simulator does not support `transferUserInfo`; physical Watch+iPhone testing is required. The macOS accessibility tree was inspected, but actual VoiceOver speech/traversal and physical touch targets remain unverified. Simulator observations do not verify iPhone file protection or locked-device behavior on hardware.

## Local verification

Run from the repository root:

```sh
DEVELOPER_DIR=/path/to/Xcode.app/Contents/Developer xcrun swiftc native/ios/Observation.swift native/shared/FictionalWatchEvent.swift native/ios/ObservationService.swift native/ios/ProtectedObservationVault.swift native/ios/ObservationBackup.swift native/ios/NativeStrings.swift native/watch/FictionalWatchOutbox.swift native/ios/Tests/main.swift -o /tmp/pdbridge-native-smoke
/tmp/pdbridge-native-smoke
native/ios/Tests/run-vault-integration.sh
node native/ios/Tests/scaffold-check.mjs
node native/ios/Tests/project-check.mjs
plutil -lint native/PDBridgeNative.xcodeproj/project.pbxproj native/ios/App/Info.plist native/watch/Info.plist
```

The cross-platform contract harness injects write failures and checks delayed/repeated delivery, post-restart deduplication, queue persistence/acknowledgment/corruption handling, simulated locked-Keychain failure/retry, protected-data cache clearing/reload, encrypted backup round trips, wrong passphrases, merge conflicts, and report inclusion. The macOS vault integration test exercises CryptoKit AES-GCM and an isolated, uniquely named disposable Keychain item; it injects failures before each deletion stage, restarts against pending markers, checks both-marker failure and one-marker recovery, blocks concurrent Watch delivery, rejects stale Watch replay, and checks idempotent retry. These checks do not establish iPhone file protection or lock/restart notification behavior on hardware. `WatchConnectivity` transfer, watchOS file protection and power-loss durability, signing, installation, VoiceOver, and print preview require appropriate hardware. Apple Simulator does not support `transferUserInfo`, so a paired physical watch is required for the complete transfer test.

The project source is `../project.yml`; its generated Xcode project is committed. The iPhone V1 target does not embed the unfinished Watch companion; that separate Watch target and its source remain available for future development and QA. Run `../project/verify_iphone_only_release.py` from `native/` after project generation to catch accidental Watch embedding. The app includes a microphone usage description for optional user-started recording, but has no speech-recognition or transcription path. It contains no HealthKit or fall-detection entitlement and no active fall sensor code. Local notification scheduling is limited to the user's single optional reminder. `EntitlementGatedFallAdapter.swift` contains an opt-in compile-time scaffold that is unavailable in normal project builds. `HealthKitFallSource.swift` remains an unlinked, disabled historical-data scaffold. See [the Apple entitlement draft](../../docs/APPLE_FALL_ENTITLEMENT_DRAFT.md) for eligibility and product-fit cautions.
